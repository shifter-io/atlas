Browser pulse: targets, outcomes, settings and bundles

The browser pulse measures real-browser targets (a marketplace product page, a search results page, AI answers and others) through each network from dedicated browser hosts. This page is the operator reference for its frozen contracts: target identities (K-BP1), outcomes (K-BP2), the settings file (K-BP3), the run bundle (K-BP4), scheduling (K-BP5) and the manager's ingest endpoint (K-BP7). The code holding them is proxy_index.browser.contracts and proxy_index.browser.settings. Snapshot and API fields (K-BP6) are documented with the calculator and the API.

Status: the names, formats and checks exist and are tested, and the orchestrator's planner (job browser_plan, Scheduling) opens the browser batches. Nothing runs or uploads a browser run yet; the hosts and the ingest endpoint follow in their own changes.

1. Targets (K-BP1)

Browser targets are rows of configs/targets.toml with engine = "browser", pulse_enabled = false and census = false: the settings file schedules them, never the HTTP pulse or the census. load_targets, and so db-seed, refuses a browser row with pulse_enabled or census true. Their pulse_* columns are unused. A target's version starts at "1"; a judge or selector change bumps it.

In code a browser target is a proxy_index.targets.BrowserTarget: engine = "browser", pool_eligible = False (it records no exit IP), and build_request() only names the base URL. For each try, page(context, inputs) builds a PageSpec(url, wait_for, settle_ms) from the settings inputs; interact(driver, spec) may act on the page through a PageDriver (goto, fill, press, click, wait_for, count, text, url, title, screenshot; timeouts in milliseconds); and judge(view) returns an Assessment. The PageView holds the final URL, the main document's status, the title, the first 4 KB of visible text, the match count of each named selector and the timings. The five page targets and the three AI sources are registered in the target registry (section 2a); the HTTP runner refuses to run them.

2. Outcomes (K-BP2)

Every try lands in one of the existing verdicts. Four error codes are new, all under the error verdict, so no counter or column changes: login_wall, no_content, no_answer and browser_error.

Evaluation order: the navigation error first, then the main document's status and the shared challenge and block markers on the title plus the first 4 KB of visible text, then the target's own judge. Firefox network errors map by a fixed table (classify_navigation_error); exact names win over prefixes:

  • NS_ERROR_PROXY_* and NS_ERROR_UNKNOWN_PROXY_HOST: proxy_connect;
  • an HTTP 407 or NS_ERROR_PROXY_AUTHENTICATION_FAILED: proxy_auth;
  • NS_ERROR_NET_RESET, NS_ERROR_NET_INTERRUPT and NS_ERROR_CONNECTION_REFUSED: connection;
  • NS_ERROR_UNKNOWN_HOST: dns;
  • NS_ERROR_NET_TIMEOUT and Playwright's TimeoutError: timeout;
  • SEC_ERROR_*, SSL_ERROR_* and NS_ERROR_NET_INADEQUATE_SECURITY: tls;
  • anything else, or no name: browser_error.

2a. What counts as success

A page answering 200 is not a success: a try is ok only when the browser shows the real content below. The code is proxy_index.browser.judge (shared steps) and proxy_index.browser.targets.pages and proxy_index.browser.targets.ai (one class per target, registered in the target registry). Every judge runs the same steps in this order and stops at the first that applies:

  1. a navigation error, already mapped by the transport (the judge never sees it);
  2. a main document answered with 407: proxy error proxy_auth;
  3. a challenge: the site's own challenge signs (below), then the shared challenge markers of outcome.py ("captcha", "just a moment", "verify you are human" and the others) on the title and the first 4 KB of visible text;
  4. a block: the site's own block signs, the shared block markers ("access denied", "you have been blocked", "rate limit" and the others), then the statuses 403, 429 and 451 and the site's own block statuses;
  5. the target's pass condition.

URL paths are matched as path prefixes of whole segments: a redirect to /login or /login/... matches /login, but a profile at /in/loginov-example/ does not. A site's own sign is checked before the shared markers of the same kind. Example: Cloudflare's "you have been blocked" page carries the title "Attention Required!", which alone would read as a challenge.

AI answers are never stored. An AI source reads the answer's length and sentence count through the driver inside interact() and keeps only those numbers. The answer text is not logged, not put in the try record (which has no field for it) and not returned; an ok try of an AI source gets no screenshot, whatever [browser] screenshots says. The questions are fixed, neutral and hold no personal data; the sources are used logged out, from the network's exit. No captcha or challenge is ever solved: a challenge is recorded as one. "Stops growing" means the reply's length is unchanged for 2 seconds, read every half second.

Each failure also records a short reason in the try (captcha_page, dogs_page, no_price, no_title, no_product, sorry_page, consent_page, few_results, authwall_redirect, no_name, no_headline, login_dialog, login_redirect, no_profile, no_posts, challenge_page, cf_block, no_expect, no_overview, short_overview, no_results, no_prompt, short_answer, no_reply, too_many_requests, unusual_traffic, or for the shared steps proxy_auth_status, challenge_marker, block_marker, block_status). A judge returns a PageAssessment: an Assessment plus that reason, whose verdict is always the one its error code implies, so a try is never ok with an error.

For the transport

  • Inputs. Try i of a run uses inputs[i % n] of the target's settings inputs, so a run rotates its list deterministically. target.try_fields(context, inputs) gives the try record's input (as the settings give it) and source (null for the five page targets, the target's own id for an AI source).
  • Selectors. PageSpec.wait_for is a CSS selector list. The transport waits for it, then counts each selector that judge.selectors(wait_for) returns (split at its top-level commas) into PageView.found under the selector's own text. A selector the page lacks counts 0. A judge reads only these counts, the final URL, the status, the title and the visible text head.
  • Expected text. cloudflare_challenge puts its input's expect into the list as body:has-text("..."), so the judge reads it from found. Its interact() waits up to challenge_wait_s for that text or a Cloudflare error page. The host binds the setting with dataclasses.replace(target, challenge_wait_s=...).
  • AI sources. interact() may return named numbers; the transport adds them to PageView.found after the selector counts. The AI sources return answer_chars, answer_sentences and, when an answer appeared, answer_ms (from the question, or for ai_overview the start of the wait, to its last growth). The chat sources' page() returns an AskSpec, a PageSpec that also carries the question. A dismissible cookie or consent dialog shown at load is closed with one click. The wait ends at answer_wait_s or the try's page timeout, whichever is first: the host binds both with dataclasses.replace(target, answer_wait_s=..., page_timeout_s=...) (the target's timeout_s, else [browser] page_timeout_s). driver.text(selector) returns the visible text of the selector's first match. The transport never takes a screenshot of an ok try of a target in contracts.AI_SOURCES. The visible text head can hold the answer: the judge only matches markers in it, and nothing records it.
  • Versions. All eight are version = "1". A change to a selector, a sign or a rule bumps the target's version.

3. Settings file (K-BP3)

One file, schema = 2, read by the orchestrator's planner and by every host. load_settings(path) returns a frozen tree, and settings_sha256(path) the hash every bundle records. The real file is private: it names each host's networks and the real inputs, which can be personal data. configs/browser-pulse.example.toml shows every field with neutral placeholders.

Host state directory: settings.toml (a copy of the private file); networks/<provider>.<product>/{provider.toml, credentials.toml, node.token}, all mode 0600; camoufox/<release>/; runs/; outbox/; logs/. No storage settings or keys live on a host.

4. Run bundle (K-BP4)

One bundle per run (network × target × country × slot): the node's usual run directory (summary.json, buckets) plus browser/manifest.json, browser/tries.jsonl and browser/screenshots/NNNN.jpg (NNNN is the try index; JPEG quality 60, the viewport only, failures only by default). It is packed into outbox/<run_id>.tar.gz with outbox/<run_id>.json beside it (batch id, sha256, bytes, network, target, slot): outbox_paths(root, run_id). The tar is deterministic: sorted members, uid and gid 0, mtime the slot start, gzip level 6.

browser/manifest.json

Format proxy-index-browser-raw, version 1, built with manifest(...) and checked when read back with check_manifest(doc):

  • run_id, batch_id, network {provider, product}, target, host (the logical name);
  • country (the batch's), requested_country (null when untargeted) and geo_targeting: they must agree, and a targeted run requests its batch's country;
  • slot, started_at, finished_at: UTC, ISO 8601;
  • tries and outcomes {verdicts, errors}: every verdict and every browser error code, zeros included; each failed try has exactly one code;
  • settings_sha256, and camoufox {release, engine_version, user_agent}, whose user agent's Firefox version equals the engine's major version;
  • files [{name, bytes, sha256}]: each member once, browser/tries.jsonl always, never the manifest itself.

browser/tries.jsonl

One line per try, built with try_record(...): i (zero-based), input (the settings input exactly as given: a string, or for instagram_web and cloudflare_challenge the {site, handle} or {url, expect} object; each string at most 2048 characters), source, verdict, error (the verdict must be the one the code implies), status (main document), final_url (scheme, host and path: no credentials, query or fragment), timings_ms {queue, context, navigate, settle, total}, bytes_down_est, reason (a lower-case enum from the judge) and screenshot (this try's member or null). Records never hold page text, answer text, cookies, credentials or proxy user names: fields named text, answer, cookies, username, password, credentials, proxy or token are refused, as is any unknown field.

Storage object

Only the manager writes it: object_key(prefix, network, target, country, slot) is <prefix>/<network>/<target>/<cc>/<YYYY-MM-DDTHHMMZ>.tar.gz.

  • prefix is the database setting browser.archive_prefix (default browser-files) and never shares the top level of another archive (raw, raw-files, inputs);
  • network is network_slug(provider, product): <provider>.<product> in lower case;
  • cc is the lower-case requested country, or untargeted when the run requested none;
  • the time is the slot start (slot_stamp: UTC, whole minutes; a naive time is refused).

The object holds the exact bytes the host sent; its metadata carries sha256, run-id and batch-id.

5. Scheduling and region (K-BP5)

Browser runs are batches of kind browser. All browser hosts share one runner region: slug browser, region id 20, cloud local, pattern browser(-[a-z0-9]+)?; it is not one of the cloud regions. A host's node tokens are bound to its logical name, and the manager refuses a browser token presenting another host. Per settings target (index i of n) and country, the planner opens one batch per slot of that target's own interval, starting lead_seconds + i × interval / n into the slot; a slot opened late spreads over what is left of it, minus 10 minutes. Hosts take tries, concurrency (browsers_per_host) and timeouts from the settings file, and no try starts after the slot end minus 2 minutes. Pulse and census participants exclude browser-region nodes.

Scheduling: the orchestrator's planner

The job browser_plan (proxy_index.orchestrator.browser) runs every minute, on the minute. It plans only while the database setting browser.enabled is true (default false) and the settings file at the setting browser.settings_file (default none) loads with enabled = true; otherwise the job records skipped with the reason. The file is parsed again only when its SHA-256 changes. A file that cannot be read or does not validate raises the alert browser_settings_invalid (one alert whose occurrences count the ticks; it names the field, never a value) and nothing is planned; the alert is acknowledged once the file loads again.

  • Per-target slots. Each [[target]] has its own interval: its slot is floor(now / every_minutes) since the epoch, so an hourly target opens every hour and a 120-minute one every even UTC hour. The slot gets one batch of kind browser per [schedule] countries entry, in region 20, with scheduled_for = the slot. With the targets in file order (index i of n), target i starts lead_seconds + i × every_minutes / n into its slot, so one host's targets spread over the slot. A batch already opened for the slot is never opened again.
  • Late opening. A slot first planned more than 60 seconds after it began (a restart, the planner just switched on) spreads from now over what is left of it minus 10 minutes: target i starts now + lead_seconds + i × (slot end − 10 min − now) / n, and a target whose start would fall after the slot end minus 10 minutes waits for its next slot, which opens on time.
  • Runs. Every new batch gets a queued run for each network (product) with a node in the browser region. A batch with none closes at once as failed. Runs are handed out, reaped (not_started, stale) and reported like every other run.
  • Region. The browser region's runner_regions row (20, browser, local, its pattern) is not seeded from configs/regions.yaml; the planner and the first browser token insert it when missing. A host or region name that no cloud pattern matches but browser(-[a-z0-9]+)? does resolves to it (regions.resolve_region; regions.region_id gives the id of either kind). Census, pulse and load never plan there: a network with only browser nodes gets no census or pulse run and no no_node alert.
  • Tokens. proxy-index node-token --region browser --host browser-<n> --provider … --product … creates the network's browser node bound to that logical host name (kept in nodes.host) or rotates its token; without --host, or with a name not of the form browser-<n>, it is refused. One network has one browser node, on one host.

6. Ingest endpoint (K-BP7)

Hosts upload a bundle through the existing node route and bearer token: POST /v1/results?batch_id=<id> with Content-Type: application/gzip, X-Content-SHA256: <64 hex> (required for kind browser, verified for any kind when present) and X-Bundle-Id: <run_id> (it must equal the bundle's summary.run_id). The manager checks the checksum while it receives the body, bounds concurrent ingests, archives the exact bytes once, ingests the run directory into the database and keeps nothing.

ReplyMeaning · what the host does
200 {"ok": true, "ingested": true, "status", "run_key", "archived": {"key", "sha256"}}Stored, or an idempotent replay. The host deletes its bundle only when archived.sha256 equals its own.
200 {"ingested": false}The run was killed or skipped. The host deletes its bundle.
400 checksum_mismatchNothing kept. The host re-hashes and retries once.
409 bundle_changedAn object with other bytes exists; it is never overwritten, and the alert browser_bundle_changed is raised. The host keeps its file, marked.
429 (Retry-After), 503Busy, a duplicate in flight, or storage or the database unreachable. Retried with backoff.
any otherKept with a .conflict or .rejected marker and a log line.

confirmed(reply, local_sha256) is the single rule a host uses to delete a bundle: true only for a 200 with ingested: true and an equal archived.sha256, or a 200 with ingested: false; false for every other status and for a missing or malformed field. Nothing unconfirmed is ever deleted, and a host never reports an unconfirmed browser upload as failed.

The reported user agent is the standard Firefox one for the engine (user_agent(engine_version, os)): its Firefox version always equals the engine's major version, and a host refuses to start otherwise.

7. Install (D7)

Only browser hosts install the browser. uv sync --locked --extra browser adds the exactly pinned Camoufox Python package and Playwright with their locked dependencies; a plain uv sync --locked (CI, the orchestrator, Linux pulse nodes) installs none of them. Browser hosts add --no-dev (uv sync --locked --no-dev --extra browser): the dev group's cryptography has no macOS x86_64 wheel, so the Intel minis cannot install it. On its first launch the camoufox package downloads its pinned fingerprint model (a SHA-256-checked GitHub release asset) once; host code imports camoufox, never fpgen directly, because import fpgen fetches an unpinned model.

The browser itself is downloaded at run time, never vendored: proxy-index browser fetch --dest DIR [--platform darwin-arm64|darwin-x86_64|linux-x86_64] downloads the one pinned release's build for this machine (or the named platform) over https, checks its size and SHA-256 before unpacking anything, unpacks it into DIR/<release>/ (plain relative files and directories only, no links) and moves it into place atomically. It prints JSON with the release, the engine (Firefox) version and the executable path. A second fetch of a verified install downloads nothing; any mismatch is a refusal that leaves nothing behind, and an existing DIR/<release>/ that is not the verified build is refused, never overwritten. release.executable(DIR) returns the binary of a verified install.

The pin lives in src/proxy_index/browser/release.py: RELEASE, ENGINE_VERSION and one BUILDS row per platform (URL, SHA-256, size, executable). The minis are Intel, so the darwin-x86_64 row is required. To bump it, open a PR that changes the release and every row to the new release's URLs, sizes and SHA-256s (from the release's published asset digests, checked against a real download), and the camoufox pin in pyproject.toml to the package version paired with that browser release (its browser-pin.json), with Playwright inside that package's range, and keep the indexed-zstd constraint ([tool.uv]) only while some platform would otherwise build it from source; regenerate uv.lock remotely and fetch the new build once on Linux and on an Intel Mac before merging.
