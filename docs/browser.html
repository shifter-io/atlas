Browser pulse: targets, outcomes, settings and bundles

The browser pulse measures real-browser targets (a marketplace product page, a search results page, AI answers and others) through each network from dedicated browser hosts. This page is the operator reference for its frozen contracts: target identities (K-BP1), outcomes (K-BP2), the settings file (K-BP3), the run bundle (K-BP4), scheduling (K-BP5) and the manager's ingest endpoint (K-BP7). The code holding them is proxy_index.browser.contracts and proxy_index.browser.settings. Snapshot and API fields (K-BP6) are documented with the calculator and the API.

Status: the names, formats and checks exist and are tested, and the orchestrator's planner (job browser_plan, Scheduling) opens the browser batches. The manager's ingest endpoint (Ingest) accepts bundles. The host process (Host) runs the browser batches, seals each run into a bundle and sends it from its outbox (Bundles and outbox).

1. Targets (K-BP1)

Browser targets are rows of configs/targets.toml with engine = "browser", pulse_enabled = false and census = false: the settings file schedules them, never the HTTP pulse or the census. load_targets, and so db-seed, refuses a browser row with pulse_enabled or census true. Their pulse_* columns are unused. A target's version starts at "1"; a judge or selector change bumps it.

In code a browser target is a proxy_index.targets.BrowserTarget: engine = "browser", pool_eligible = False (it records no exit IP), and build_request() only names the base URL. For each try, page(context, inputs) builds a PageSpec(url, wait_for, settle_ms) from the settings inputs; interact(driver, spec) may act on the page through a PageDriver (goto, fill, press, click, wait_for, count, text, url, title, screenshot; timeouts in milliseconds); and judge(view) returns an Assessment. The PageView holds the final URL, the main document's status, the title, the first 4 KB of visible text, the match count of each named selector and the timings. The five page targets and the three AI sources are registered in the target registry (section 2a); the HTTP runner refuses to run them.

2. Outcomes (K-BP2)

Every try lands in one of the existing verdicts. Four error codes are new, all under the error verdict, so no counter or column changes: login_wall, no_content, no_answer and browser_error.

Evaluation order: the navigation error first, then the main document's status and the shared challenge and block markers on the title plus the first 4 KB of visible text, then the target's own judge. Firefox network errors map by a fixed table (classify_navigation_error); exact names win over prefixes:

  • NS_ERROR_PROXY_* and NS_ERROR_UNKNOWN_PROXY_HOST: proxy_connect;
  • an HTTP 407 or NS_ERROR_PROXY_AUTHENTICATION_FAILED: proxy_auth;
  • NS_ERROR_NET_RESET, NS_ERROR_NET_INTERRUPT and NS_ERROR_CONNECTION_REFUSED: connection;
  • NS_ERROR_UNKNOWN_HOST: dns;
  • NS_ERROR_NET_TIMEOUT and Playwright's TimeoutError: timeout;
  • SEC_ERROR_*, SSL_ERROR_* and NS_ERROR_NET_INADEQUATE_SECURITY: tls;
  • anything else, or no name: browser_error.

2a. What counts as success

A page answering 200 is not a success: a try is ok only when the browser shows the real content below. The code is proxy_index.browser.judge (shared steps) and proxy_index.browser.targets.pages and proxy_index.browser.targets.ai (one class per target, registered in the target registry). Every judge runs the same steps in this order and stops at the first that applies:

  1. a navigation error, already mapped by the transport (the judge never sees it);
  2. a main document answered with 407: proxy error proxy_auth;
  3. a challenge: the site's own challenge signs (below), then the shared challenge markers of outcome.py ("captcha", "just a moment", "verify you are human" and the others) on the title and the first 4 KB of visible text;
  4. a block: the site's own block signs, the shared block markers ("access denied", "you have been blocked", "rate limit" and the others), then the statuses 403, 429 and 451 and the site's own block statuses;
  5. the target's pass condition.

URL paths are matched as path prefixes of whole segments: a redirect to /login or /login/... matches /login, but a profile at /in/loginov-example/ does not. A site's own sign is checked before the shared markers of the same kind. Example: Cloudflare's "you have been blocked" page carries the title "Attention Required!", which alone would read as a challenge.

AI answers are never stored. An AI source reads the answer's length and sentence count through the driver inside interact() and keeps only those numbers. The answer text is not logged, not put in the try record (which has no field for it) and not returned. A try of an AI source gets no screenshot once any answer text was shown (answer_chars above 0), whether it is ok or not and whatever [browser] screenshots says, so no screenshot holds an answer either. The questions are fixed, neutral and hold no personal data; the sources are used logged out, from the network's exit. No captcha or challenge is ever solved: a challenge is recorded as one. "Stops growing" means the reply's length is unchanged for 2 seconds, read every half second.

Each failure also records a short reason in the try (captcha_page, dogs_page, no_price, no_title, no_product, not_found, empty_page, sorry_page, consent_page, few_results, authwall_redirect, no_name, no_headline, login_dialog, login_redirect, no_profile, no_posts, challenge_page, cf_block, no_expect, no_overview, short_overview, no_results, no_prompt, short_answer, no_reply, too_many_requests, unusual_traffic, or for the shared steps proxy_auth_status, challenge_marker, block_marker, block_status). A judge returns a PageAssessment: an Assessment plus that reason, whose verdict is always the one its error code implies, so a try is never ok with an error.

For the transport

  • Inputs. Try i of a run uses inputs[i % n] of the target's settings inputs, so a run rotates its list deterministically. target.try_fields(context, inputs) gives the try record's input (as the settings give it) and source (null for the five page targets, the target's own id for an AI source).
  • Selectors. PageSpec.wait_for is a CSS selector list. The transport waits for it, then counts each selector that judge.selectors(wait_for) returns (split at its top-level commas) into PageView.found under the selector's own text. A selector the page lacks counts 0. A judge reads only these counts, the final URL, the status, the title and the visible text head.
  • Expected text. cloudflare_challenge puts its input's expect into the list as body:has-text("..."), so the judge reads it from found. Its interact() waits up to challenge_wait_s for that text or a Cloudflare error page. The host binds the setting with dataclasses.replace(target, challenge_wait_s=...).
  • AI sources. interact() may return named numbers; the transport adds them to PageView.found after the selector counts. The AI sources return answer_chars, answer_sentences and, when an answer appeared, answer_ms (from the question, or for ai_overview the start of the wait, to its last growth). The chat sources' page() returns an AskSpec, a PageSpec that also carries the question. A dismissible cookie or consent dialog shown at load is closed with one click. The wait ends at answer_wait_s or the try's page timeout, whichever is first: the host binds each one that is set with dataclasses.replace(target, answer_wait_s=..., page_timeout_s=...) (the page timeout is the target's timeout_s, else [browser] page_timeout_s); an unset answer_wait_s keeps the default 30 seconds. driver.text(selector) returns the visible text of the selector's first match. The transport never takes a screenshot of a try of a target in contracts.AI_SOURCES whose found holds answer_chars above 0. The visible text head can hold the answer: the judge only matches markers in it, and nothing records it.
  • Versions. All eight are version = "1". A change to a selector, a sign or a rule bumps the target's version.

3. Settings file (K-BP3)

One file, schema = 2, read by the orchestrator's planner and by every host. load_settings(path) returns a frozen tree, and settings_sha256(path) the hash every bundle records. The real file is private: it names each host's networks and the real inputs, which can be personal data. configs/browser-pulse.example.toml shows every field with neutral placeholders.

Host state directory: settings.toml (a copy of the private file); networks/<provider>.<product>/{provider.toml, credentials.toml, node.token}, all mode 0600; camoufox/<release>/; runs/; outbox/; logs/. No storage settings or keys live on a host.

4. Run bundle (K-BP4)

One bundle per run (network × target × country × slot): the node's usual run directory (summary.json, buckets) plus browser/manifest.json, browser/tries.jsonl and browser/screenshots/NNNN.jpg (NNNN is the try index; JPEG quality 60, the viewport only, failures only by default). It is packed into outbox/<run_id>.tar.gz with outbox/<run_id>.json beside it (batch id, sha256, bytes, network, target, slot): outbox_paths(root, run_id). The tar is deterministic: sorted members, uid and gid 0, mtime the slot start, gzip level 6.

browser/manifest.json

Format proxy-index-browser-raw, version 1, built with manifest(...) and checked when read back with check_manifest(doc):

  • run_id, batch_id, network {provider, product}, target, host (the logical name);
  • country (the batch's), requested_country (null when untargeted) and geo_targeting: they must agree, and a targeted run requests its batch's country;
  • slot, started_at, finished_at: UTC, ISO 8601;
  • tries and outcomes {verdicts, errors}: every verdict and every browser error code, zeros included; each failed try has exactly one code;
  • settings_sha256, and camoufox {release, engine_version, user_agent}, whose user agent's Firefox version equals the engine's major version;
  • files [{name, bytes, sha256}]: each member once, browser/tries.jsonl always, never the manifest itself.

browser/tries.jsonl

One line per try, built with try_record(...): i (zero-based), input (the settings input exactly as given: a string, or for instagram_web and cloudflare_challenge the {site, handle} or {url, expect} object; each string at most 2048 characters), source, verdict, error (the verdict must be the one the code implies), status (main document), final_url (scheme, host and path: no credentials, query or fragment), timings_ms {queue, context, navigate, settle, total}, bytes_down_est, reason (a lower-case enum from the judge) and screenshot (this try's member or null). Records never hold page text, answer text, cookies, credentials or proxy user names: fields named text, answer, cookies, username, password, credentials, proxy or token are refused, as is any unknown field.

Storage object

Only the manager writes it: object_key(prefix, network, target, country, slot) is <prefix>/<network>/<target>/<cc>/<YYYY-MM-DDTHHMMZ>.tar.gz.

  • prefix is the database setting browser.archive_prefix (default browser-files) and never shares the top level of another archive (raw, raw-files, inputs);
  • network is network_slug(provider, product): <provider>.<product> in lower case;
  • cc is the lower-case requested country, or untargeted when the run requested none;
  • the time is the slot start (slot_stamp: UTC, whole minutes; a naive time is refused).

The object holds the exact bytes the host sent; its metadata carries sha256, run-id and batch-id.

5. Scheduling and region (K-BP5)

Browser runs are batches of kind browser. All browser hosts share one runner region: slug browser, region id 20, cloud local, pattern browser(-[a-z0-9]+)?; it is not one of the cloud regions. A host's node tokens are bound to its logical name, and the manager refuses a browser token presenting another host. Per settings target (index i of n) and country, the planner opens one batch per slot of that target's own interval, starting lead_seconds + i × interval / n into the slot; a slot opened late spreads over what is left of it, minus 10 minutes. Hosts take tries, concurrency (browsers_per_host) and timeouts from the settings file, and no try starts after the slot end minus 2 minutes. Pulse and census participants exclude browser-region nodes.

Scheduling: the orchestrator's planner

The job browser_plan (proxy_index.orchestrator.browser) runs every minute, on the minute. It plans only while the database setting browser.enabled is true (default false) and the settings file at the setting browser.settings_file (default none) loads with enabled = true; otherwise the job records skipped with the reason. The file is parsed again only when its SHA-256 changes. A file that cannot be read or does not validate raises the alert browser_settings_invalid (one alert whose occurrences count the ticks; it names the field, never a value) and nothing is planned; the alert is acknowledged once the file loads again.

  • Per-target slots. Each [[target]] has its own interval: its slot is floor(now / every_minutes) since the epoch, so an hourly target opens every hour and a 120-minute one every even UTC hour. The slot gets one batch of kind browser per [schedule] countries entry, in region 20, with scheduled_for = the slot. With the targets in file order (index i of n), target i starts lead_seconds + i × every_minutes / n into its slot, so one host's targets spread over the slot. A batch already opened for the slot is never opened again.
  • Late opening. A slot first planned more than 60 seconds after it began (a restart, the planner just switched on) spreads from now over what is left of it minus 10 minutes: target i starts now + lead_seconds + i × (slot end − 10 min − now) / n, and a target whose start would fall after the slot end minus 10 minutes waits for its next slot, which opens on time.
  • Runs. Every new batch gets a queued run for each network (product) with a node in the browser region. A batch with none closes at once as failed. Runs are handed out, reaped (not_started, stale) and reported like every other run.
  • Region. The browser region's runner_regions row (20, browser, local, its pattern) is not seeded from configs/regions.yaml; the planner and the first browser token insert it when missing. A host or region name that no cloud pattern matches but browser(-[a-z0-9]+)? does resolves to it (regions.resolve_region; regions.region_id gives the id of either kind). Census, pulse and load never plan there: a network with only browser nodes gets no census or pulse run and no no_node alert.
  • Tokens. proxy-index node-token --region browser --host browser-<n> --provider … --product … creates the network's browser node bound to that logical host name (kept in nodes.host) or rotates its token; without --host, or with a name not of the form browser-<n>, it is refused. One network has one browser node, on one host.

6. Ingest endpoint (K-BP7)

Hosts upload a bundle through the existing node route and bearer token: POST /v1/results?batch_id=<id> with Content-Type: application/gzip, X-Content-SHA256: <64 hex> (required for kind browser, verified for any kind when present) and X-Bundle-Id: <run_id> (it must equal the bundle's summary.run_id). The manager checks the checksum while it receives the body, bounds concurrent ingests, archives the exact bytes once, ingests the run directory into the database and keeps nothing.

ReplyMeaning · what the host does
200 {"ok": true, "ingested": true, "status", "run_key", "archived": {"key", "sha256"}}Stored, or an idempotent replay. The host deletes its bundle only when archived.sha256 equals its own.
200 {"ingested": false}The run was killed or skipped. The host deletes its bundle.
400 checksum_mismatchNothing kept. The host re-hashes and retries once.
409 bundle_changedAn object with other bytes exists; it is never overwritten, and the alert browser_bundle_changed is raised. The host keeps its file, marked.
429 (Retry-After), 503Busy, a duplicate in flight, or storage or the database unreachable. Retried with backoff.
any otherKept with a .conflict or .rejected marker and a log line.

confirmed(reply, local_sha256) is the single rule a host uses to delete a bundle: true only for a 200 with ingested: true and an equal archived.sha256, or a 200 with ingested: false; false for every other status and for a missing or malformed field. Nothing unconfirmed is ever deleted, and a host never reports an unconfirmed browser upload as failed.

What the manager does (orchestrator/browser_ingest.py)

  1. Receive. The body is streamed to a private temporary file under results.max_upload_bytes while it is hashed; a different sha256 answers 400 checksum_mismatch and nothing is kept. A browser node that never registered gets 403.
  2. Bound. At most browser.ingest_concurrency bundles (default 4) are processed at once by the orchestrator process (429, Retry-After: 30), and one per (batch, network) by any process: a PostgreSQL advisory try-lock held on a connection of its own (429, Retry-After: 10 for a duplicate already in flight).
  3. Run state, read again under the lock: killed or skipped answers 200 ingested: false; a finished run with a run_key is a replay, answered 200 only when its object holds the same sha256 (no database change); running, uploading, or failed by the reaper without a run_key (a late upload) continues; anything else is 409.
  4. Unpack with the run archive's limits (the K-BP4 browser/ members besides), then check network, target, batch, country and run id against the node, the batch, X-Bundle-Id and browser/manifest.json, validate the manifest and the size and sha256 of every file it lists. The manifest's requested_country and geo_targeting must agree with the run's summary. A mismatch answers 400, fails the run and raises results_rejected; a manifest naming another host answers 403.
  5. Archive the received bytes once to <browser.archive_prefix>/<provider>.<product>/<target>/<cc>/<slot>.tar.gz, where cc is the summary's requested country or untargeted (D11), with the metadata sha256, run-id and batch-id. ARCHIVE-1's Spaces.put_verified does HEAD, PUT when absent, HEAD again, and compares bytes, MD5 and sha256. An object already there with the same sha256 counts as stored; one with another sha256 answers 409 bundle_changed with the alert browser_bundle_changed and is never overwritten.
  6. Database: storage.ingest of the run directory without browser/, without per-IP rows (idempotent by run id), then batches.finish_run. A late run goes back to uploading (and its batch, if the reaper closed it, back to running) first, so it becomes done with its run_key and the batch closes again with its status recomputed.
  7. Clean up: every temporary file is deleted before the reply, whatever the answer. The manager keeps nothing; the generic raw spool (raw.spool_dir) is skipped for kind browser, the bundle being archived per run.
  8. Reply 200 as in the table above. The storage or the database unreachable answers 503 at any step; a retry finds the stored object and the ingested run and finishes without duplicates.

Uploads from the three minis at once are therefore safe: each bundle has its own temporary directory, run lock and object key, and an interrupted upload is completed by the next try. Before an upload the host must have registered, and its token is bound to its host's logical name (D2): /v1/register refuses a browser token with another host (403), and so does an upload whose manifest names another host. Other kinds keep their behaviour; a pulse or census node may send X-Content-SHA256 too and then gets 400 on a mismatch.

Manager runbook

  • Settings: archive.spaces_file (the [spaces] file ARCHIVE-1 deploys; production) and optionally browser.archive_prefix (default browser-files) and browser.ingest_concurrency (default 4; each ingest holds one extra database connection). browser.archive_dir writes the same keys to a local directory instead of Spaces, with each object's metadata in <object>.meta.json: for staging (BP-VERIFY-1) and tests only, never in production. Without either, a browser upload answers 503 archive_not_configured.
  • Alerts: browser_bundle_changed (major; an archived bundle and a new upload of it differ: compare the two before anything is deleted, the host keeps its copy marked), results_rejected and ingest_failed (a bundle or its data was refused; the run failed).

Manager firewall

The browser hosts reach the node API port (8443, HTTPS) through the manager's cloud firewall. Its node API rule admits the pulse-node tag and, as /32 sources, the public IPv4 of each browser host; SSH from the Mac and the outbound rules are not touched. The addresses are recorded in the manager inventory (browser_host_ipv4s), so every later rebuild of the firewall keeps them: deploy, allow-me when the Mac's address changes, and orchestrator-enable. The rule exists only while the orchestrator's port is open (orchestrator-enable first); orchestrator-disable closes it and keeps the recorded addresses for the next enable.

  1. Read each host's public IPv4 on that host: curl -s https://api.ipify.org. The minis share the home connection, so they usually print the same address; give it once.
  2. Dry run (changes nothing; prints the node API rule before and after): proxy-index campaign manager browser-hosts --ip ADDRESS[,ADDRESS...] --inventory INVENTORY. The inventory is the proxy-index account's; the DigitalOcean token is read from its keychain item, never from the command line.
  3. Apply: the same command with --apply. It checks the account, sets exactly the given addresses (replacing any earlier ones), reads the firewall back and records the addresses only when the read-back holds exactly them. A different read-back fails and leaves the inventory unchanged; compare the firewall with the DigitalOcean console before retrying.
  4. Remove every browser host: --clear --apply.

Only distinct public IPv4 addresses are accepted, at most 8: a private, loopback, link-local, shared (CGNAT), multicast or documentation address, an IPv6 address, a network such as /24 or a repeated address is refused before anything is sent.

When the home connection's address changes, the hosts' connections to the manager fail and their bundles stay in the outbox (a network error keeps a bundle; nothing unconfirmed is deleted). Read the new address on a mini as in step 1 and run the command again with it and --apply; the old address is removed in the same change. The outbox sends the waiting bundles again with its backoff, at most 5 minutes later.

The reported user agent is the standard Firefox one for the engine (user_agent(engine_version, os)): its Firefox version always equals the engine's major version, and a host refuses to start otherwise.

7. Install (D7)

Only browser hosts install the browser. uv sync --locked --extra browser adds the exactly pinned Camoufox Python package and Playwright with their locked dependencies; a plain uv sync --locked (CI, the orchestrator, Linux pulse nodes) installs none of them. Browser hosts add --no-dev (uv sync --locked --no-dev --extra browser): the dev group's cryptography has no macOS x86_64 wheel, so the Intel minis cannot install it. On its first launch the camoufox package downloads its pinned fingerprint model (a SHA-256-checked GitHub release asset) once; host code imports camoufox, never fpgen directly, because import fpgen fetches an unpinned model.

The browser itself is downloaded at run time, never vendored: proxy-index browser fetch --dest DIR [--platform darwin-arm64|darwin-x86_64|linux-x86_64] downloads the one pinned release's build for this machine (or the named platform) over https, checks its size and SHA-256 before unpacking anything, unpacks it into DIR/<release>/ (plain relative files and directories only, no links) and moves it into place atomically. It prints JSON with the release, the engine (Firefox) version and the executable path. A second fetch of a verified install downloads nothing; any mismatch is a refusal that leaves nothing behind, and an existing DIR/<release>/ that is not the verified build is refused, never overwritten. release.executable(DIR) returns the binary of a verified install.

The pin lives in src/proxy_index/browser/release.py: RELEASE, ENGINE_VERSION and one BUILDS row per platform (URL, SHA-256, size, executable). The minis are Intel, so the darwin-x86_64 row is required. To bump it, open a PR that changes the release and every row to the new release's URLs, sizes and SHA-256s (from the release's published asset digests, checked against a real download), and the camoufox pin in pyproject.toml to the package version paired with that browser release (its browser-pin.json), with Playwright inside that package's range, and keep the indexed-zstd constraint ([tool.uv]) only while some platform would otherwise build it from source; regenerate uv.lock remotely and fetch the new build once on Linux and on an Intel Mac before merging.

8. Runner

A browser target runs through the ordinary runner, so it gets the same counters, buckets and summary as an HTTP run: runner.run(config, sink, targets=..., transport_factory=BrowserTransport.factory(pool, recorder, browser=settings.browser, settings=target_settings, deadline=...)). Three modules make the engine (src/proxy_index/browser/):

  • driver.py is the only module that imports Playwright or Camoufox. launch(release.executable(DIR), locale=..., headless=...) starts the pinned browser through Camoufox's own launch options: the fingerprint OS is the host's (macos or linux), locale and headless come from [browser], and geoip is off, because its lookup is a request outside the proxy. Contexts are plain Playwright contexts with the launch's identity; Camoufox's per-context identity is not used, since it also looks up the proxy's exit address.
  • pool.py: BrowserPool(size, launch, recycle_after=...), one per host and shared by every run on it (browsers_per_host processes). async with pool.browser() leases one process for one try; leases are granted first in, first out, so concurrent runs interleave. A process is launched on first use, replaced after recycle_after tries, and replaced at once when a lease ends with it disconnected (a crash; that try records browser_error), or when a lease is granted with it disconnected (it died while idle). stats() gives leases, waits, launches, recycles, crashes, closes and the resident memory of the host process's descendants. Closing the pool closes every browser and its driver; a lease still held is closed when it ends, and nothing launches after the close. Every launch ends in exactly one recycle, crash or close.
  • transport.py: BrowserTransport, the runner's Transport.

One try

  1. The proxy is config.proxy.resolve(context). An HTTP proxy is used with its username and password. SOCKS5 with credentials is refused before any traffic, since the browser cannot authenticate to it: the try records proxy_connect with reason socks5_auth_unsupported, and the host logs the network once (the pool keeps the logged networks).
  2. queue: wait for a lease. context: a new context through the proxy, with every request of a block_resources type aborted at the route level ([browser], or the target's own list); the context is closed however the try ends.
  3. navigate: load the page, within page_timeout_s (or the target's timeout_s). A failed navigation is mapped by classify_navigation_error; its reason is the lower-cased error name.
  4. settle: on google_search, a consent page or form that hides the results is accepted with one click; then the wait for wait_for, the target's settle_ms and its interact().
  5. The PageView (final URL, main document status, title, first 4 KB of visible text, selector counts, then the named numbers interact() returned) goes to target.judge(). A returned name that is also a selector, or a value that is not an integer, is refused as browser_error.

The Outcome's latency_ms is navigate plus settle: the wait for a browser is not latency. status is the main document's, bytes_down is bytes_down_est, the summed body sizes of every response the context saw (bytes_exact false). The try record carries timings_ms {queue, context, navigate, settle, total}; a step that did not run is null. Every try goes to the recorder, try_done(record, screenshot), with a validated tries.jsonl record; the default recorder keeps nothing. A screenshot (JPEG quality 60, the viewport) is taken per screenshots: failures (default), all or none, but never of a try of an AI source (contracts.AI_SOURCES) whose found holds answer_chars above 0, whatever the setting.

User agent (D7)

At launch the driver reads the engine version and navigator.userAgent. When the user agent's Firefox major is not the engine's, every context gets contracts.user_agent(engine, os) instead; when even that does not show, the launch is refused (UserAgentRefused) and the run fails. Browser.identity is the manifest's camoufox block.

Limits

  • Deadline: runner.run(deadline=...) starts no try at or after it and cancels the tries still in flight when it passes. A cancelled try has no Outcome and no recorder call, so tries.jsonl holds no line for it. The transport's own deadline (BrowserTransport.factory(..., deadline=...)) is the backstop for any other caller: it cancels a try still running at the deadline plus one page timeout and records it as timeout, reason deadline.
  • Every Playwright action of a try (clicks, waits, reading the page) times out after the page timeout, never Playwright's own 30-second default. A consent page without its accept control is not clicked; the judge reads it (consent_page).
  • Refused proxy credentials: Firefox gives up with NS_ERROR_PROXY_CONNECTION_REFUSED (seen live with the pinned release), which the K-BP2 table maps to proxy_connect; proxy_auth appears only when a 407 is the page's own status.
  • Any other exception, a browser crash included, is browser_error, with the exception's class name, lower-cased, as its reason; a refused user agent ends the run.
  • Live check: sh scripts/ci/browser_live.sh, remote only (a disposable Linux server, the pool's Mac class). It installs the pinned uv when absent, uv sync --locked --no-dev --extra browser, fetches the browser and runs pytest -m browser_live with pytest at its uv.lock versions: the real browser against tests/browser_site.py, a local site with one page per outcome behind a local authenticated proxy. CI never installs a browser; there the live tests skip.

9. Host

One process per browser host runs every network the settings assign to it:

proxy-index browser-node --settings STATE/settings.toml --state STATE --host browser-1 --orchestrator URL

It loads the settings and takes that host's [[host]] view. For each network provider/product it reads STATE/networks/<provider>.<product>/{provider.toml, credentials.toml, node.token}; each must be a regular file owned by the host's user with mode 0600 (no link is followed), and a missing or readable file stops the start. Each network is one ordinary node agent (BrowserAgent, a proxy_index.node.NodeAgent whose registry, config_options and run_options hooks come from the host) with its own token, registered as region browser with the host's logical name, working in STATE/runs/<provider>.<product>/. All of them share one BrowserPool of browsers_per_host browsers, launched from STATE/camoufox/<release>/ on the first try. A network that cannot register (a refused token) stops the whole process, so the service manager restarts it and the failure shows. With enabled = false the process starts, runs nothing and waits for its stop signal.

One assignment

  • Only kind browser runs. Another kind is reported failed as node error (UnexpectedKind), a target that is not a [[target]] of the settings as node error (UnknownTarget).
  • The assignment's pulse values (requests, concurrency, timeout) are ignored. The run takes the target's tries as its request count and browsers_per_host as its concurrency (the pool, not the run, limits the browsers); its timeout_seconds is the page timeout (timeout_s or page_timeout_s) plus the answer wait of an AI source (cut to the page timeout) or the challenge wait of cloudflare_challenge.
  • Targets come from a host registry: copies of the code targets with challenge_wait_s, answer_wait_s and the page timeout bound from the settings (dataclasses.replace, no global state).
  • Deadline: the end of the target's slot holding start_at (floor(start_at / every_minutes) + every_minutes) minus 2 minutes. No try starts at or after it, and a run whose deadline has passed starts no try and uploads an empty run.
  • Untargeted networks ([networks] untargeted, D11) build their proxy with no country parameter and rotating sessions; their runs record requested_country = null. Every other network gets the batch country as ordinary nodes do.
  • On SIGTERM or SIGINT no new try starts; running runs end as a node's do (reported failed as node_shutdown, a run not yet started is handed out again), then the pool closes every browser.

Logs

STATE/logs/browser-node.jsonl holds JSON lines, rotated at 20 MB with 5 old files kept. Each finished run writes one "kind": "run" line: batch, network, target, country, geo_targeting, tries_requested, tries_done, ok, latency_ms {p50, p90} (navigate plus settle), browser_seconds (time tries held a browser), queue_wait_ms_p50, deadline and finished_before_deadline. Every hour the host writes a "kind": "hour" line: browser_seconds of the hour, utilization = browser-seconds ÷ (browsers × 3600), the pool's stats() and the process's resident memory (rss_mb), and the outbox: outbox_pending (bundles still to send), outbox_bytes (all bundles kept, marked ones included), confirmed_last_hour, rejected, conflicts, discarded (half runs deleted at this start, see After a crash) and unsealed (finished run directories kept unsealed: not sealable at start or since). When the disk guard refuses a screenshot it writes a "kind": "browser_outbox_full" line, at most once an hour. Ordinary log messages go to standard error (types only, never credentials).

Check before installing

proxy-index browser-node --settings ... --state ... --host browser-1 --check [--browsers N] checks the settings and every network's files and provider configuration, opens N browsers (default 1, at most 16) at the same time, each checking the user-agent rule at launch, prints JSON with the pinned release, the engine and its version, the user agent and the resident memory each browser added and in total, closes them and exits. It sends no proxy traffic and needs no orchestrator. A missing install, a bad file or a refused user agent exits with status 2.

Service templates

configs/launchd/com.proxyindex.browser-node.plist.example (macOS, a launchd agent) and configs/systemd/proxy-index-browser-node.service.example (Linux) run the command above, restart it when it exits and stop it with SIGTERM (120 s before a kill). They hold placeholders only (__CHECKOUT__, __STATE__, __HOST__, __ORCHESTRATOR__, __USER__); the real values are filled in privately on each host. Standard output and error go to STATE/logs/browser-node.{out,err}.log under launchd and to the journal under systemd.

10. Bundles and outbox (browser/rawfiles.py)

On the host every run becomes one K-BP4 bundle (section 4), sent to the manager's ingest endpoint (section 6) and deleted only when the manager confirms it.

Layout

  • STATE/runs/<provider>.<product>/<run_id>/: the node's run directory while the run is going. FileRecorder, the transport's recorder, appends one validated contracts.try_record(...) line per try to browser/tries.jsonl and writes each screenshot to browser/screenshots/NNNN.jpg. It also keeps the batch facts the summary does not hold (batch id, country, slot, host, settings sha256) in browser/batch.json; that file is not a bundle member and is never packed.
  • STATE/outbox/<run_id>.tar.gz and its sidecar <run_id>.json (batch_id, sha256, bytes, network, target, country, slot), both mode 0600. A kept bundle may have a marker beside it: <run_id>.conflict or <run_id>.rejected, JSON with the reply's status, its error code and the time.

Sealing

When a run ends, seal(run_dir, batch, summary, settings_sha256, camoufox, outbox=...) writes browser/manifest.json (counts from the tries, requested_country and geo_targeting from the run's config, so an untargeted run says so, D11; the camoufox block of the last browser the host launched, else the pinned release's), packs the directory with orchestrator.archive.pack(..., nested=..., mtime=slot start) (sorted members, uid and gid 0, mode 0600, gzip level 6: identical inputs give identical bytes), fsyncs the tar.gz, writes and fsyncs the sidecar, re-hashes the tar.gz against it and only then removes the run directory. A run that cannot be sealed keeps its directory and is sealed at the next start. A run the orchestrator killed, and one stopped by a shutdown, is removed without upload, as on any node.

Sending and the confirmation rule

Outbox.send(bundle, agent) posts the tar.gz through the network's own node agent (its session, token and POST /v1/results?batch_id=) with Content-Type: application/gzip, X-Content-SHA256 (the file's sha256) and X-Bundle-Id (the run id). The reply decides, through contracts.confirmed(reply, sha256) and nothing else:

  • 200 with ingested: true and archived.sha256 equal to the file's, or 200 with ingested: false (run killed or skipped): the tar.gz, then the sidecar, are deleted.
  • 429, 503, any other 5xx and network errors: kept, sent again later with backoff (30 s, doubling, at most 5 minutes; a longer Retry-After wins).
  • 400 checksum_mismatch: the file is re-hashed and sent once more; a second mismatch marks it .rejected.
  • 409, and a 200 that does not confirm (another sha256, missing fields): kept with .conflict. Any other 4xx: kept with .rejected. Both are logged once and not sent again until the marker is removed.

An unconfirmed upload never fails the run and never calls /v1/failed: the manager accepts a late upload (K-BP7). A loop sends the pending bundles, oldest slot first and at most 2 at a time per host, after every run end, when a network registers (host start) and every 5 minutes, with no time limit. Each bundle goes through the agent of its sidecar's network.

Disk guard

When runs/ plus the outbox hold more than [outbox] max_pending_gb (measured at most once a minute), the recorder writes no screenshot and records the try with screenshot = null; tries go on, and nothing is deleted to make room. The first refused screenshot of each hour logs browser_outbox_full.

After a crash

At start, before any network registers, recover() seals every run directory a killed process left with its summary.json (a tar.gz without its sidecar is rebuilt), removes a run directory whose bundle is already sealed and verified, and removes half-written sidecars and those of bundles already confirmed. A directory without summary.json was killed during its run: it is half a run, which the manager cannot ingest, so it is deleted, never sealed or uploaded, logged once with its run id (browser_run_discarded) and counted as discarded; the disk guard no longer counts it. Only full runs are uploaded. A finished directory whose files cannot be read or sealed (an unreadable sidecar beside it, say) is kept with its files, logged by error type and counted as unsealed, and the start goes on. A run whose seal fails while the host runs is counted the same way and sealed at the next start. Nothing finished or unconfirmed is deleted: a run with summary.json and every bundle in the outbox stay. An outbox pass never sends a bundle whose seal has not ended.

Inspecting a pending bundle on a host

ls -l STATE/outbox/                          # bundles, sidecars, markers
cat STATE/outbox/RUN_ID.json                 # batch, network, target, slot, sha256
shasum -a 256 STATE/outbox/RUN_ID.tar.gz     # must equal the sidecar's sha256
tar -tzvf STATE/outbox/RUN_ID.tar.gz         # members: summary.json, buckets, browser/...
tar -xzOf STATE/outbox/RUN_ID.tar.gz browser/manifest.json
cat STATE/outbox/RUN_ID.conflict             # why a bundle is held: status and error

To send a marked bundle again, remove its marker; the next pass sends it. Never delete a bundle the manager has not confirmed.
