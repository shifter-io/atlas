Provider credential grammars

Every provider encodes targeting and sessions differently. Each one has a reviewed grammar in src/atlas/providers/grammars/<provider>.toml, read by one shared engine (providers.grammar loads and checks it, providers.flags validates and renders each flag and reads the [testing] table, and providers.proxy.GrammarProxy resolves a run config through it), and a public run config in configs/<provider>.toml. Private credentials stay in .secrets/credentials.toml, one table per provider.

Common parameters

Parameters use the same names for every provider and are translated to the provider's own keys: country, region, city, zip, asn, session and ttl. ttl is always in minutes; the grammar converts it to the provider's unit. Provider-only options keep their own names (for example network, filter, mode, strict). Unknown parameters are rejected before any traffic, because most gateways silently ignore misspelled flags and return untargeted IPs.

uv run --no-editable atlas run --provider-config configs/oxylabs.toml \
  --credentials-file .secrets/credentials.toml --target generic_http \
  --requests 100 --param country=us --session-policy per_request

Session policies

  • rotate: no session; the gateway assigns a new exit per request (Webshare adds -rotate).
  • gateway: no session; the port or dashboard decides (Geonode sticky ports, Proxy-Seller lists).
  • fixed: the supplied session is reused; inferred when a session is given.
  • per_request, per_worker, per_run: IDs generated from the run ID and scope, in each provider's allowed alphabet and length. Proxy-Seller selects a port slot instead (see below).

Proxy-Seller: the credentials are its "API tool" login (PUT resident/list/tools), one login for every country; _c_CC picks the country. A dashboard list login ignores _c_ (its list's country applies), so it is not used. The grammar's country flag lists the countries Proxy-Seller serves (countries, from its resident/geo reference); another country raises NoCountryList ("no proxy-seller exits in KP") before traffic, and an onboarding round marks it no_list (onboarding). Without a session each request gets a new exit. The default policy is per_request: request n of a run uses port 10000 + (n mod 1000), spreading concurrent requests over the ports, with no session. A port alone keeps no exit on this login, so sticky policies also send the slot as the documented _s_SLOT session (the grammar's [session] slot_flag): a fixed session parameter selects port 10000 + slot and _s_SLOT; per_worker and per_run take a hashed slot; gateway keeps port 10000 without a session.

Proxy-Seller known limits: a sticky session's name is just the time slot, so two runs in the same slot share one exit IP; and the generic preset machinery in the provider settings has no user yet.

Provider rules are enforced: Proxy-Cheap sessions are eight digits and require ttl; SOAX needs at least one targeting flag and lowercase countries; IPRoyal sessions are eight characters; Evomi sessions are 6–10 characters.

Proxy-Cheap: countries are sent uppercase, as its dashboard generator does. In the 24-hour campaign it had very low success, mostly timeouts, limited by the account's throughput and few exit IPs per country, not by our setup; campaigns keep it unchanged and report it as measured.

Preset flags: a grammar flag with preset = true is set on the provider's side and never rendered into the credential. It suits a login whose geography is chosen on the provider's side, such as a dashboard list (no shipped grammar uses one now). The run config declares the value, for example presets = { country = "us" } under [settings]. A request for that country (a census round, a probe, --param country=US or the --country us label) sends the plain login and is labelled with it; any other country is refused before traffic, so a run is never labelled with a country its exits do not have.

Plain HTTP targets

Byteful and Infatica answered every plain-HTTP request with a gateway 301 to HTTPS on 2026-10-22, and FleetProxy, ProxyEmpire and Proxy-Cheap answered 42–46% that way. The redirect carries no CDN headers, so it comes from the proxy path, not the target. Each grammar therefore declares how its network runs the echo test in an optional [testing] table:

  • protocol = "https-only" (Byteful, Infatica): a plain-HTTP echo target such as generic_http runs at the same URL over HTTPS before any request is sent, so the network never receives plain HTTP. Other plain-HTTP targets are refused. The run's target.url shows the HTTPS URL.
  • protocol = "mixed" (FleetProxy, ProxyEmpire, Proxy-Cheap): the request goes out over HTTP; a gateway redirect (301, 302, 303, 307, 308) to the same host over HTTPS is followed once, through the same proxy session and within the same timeout. The HTTPS answer decides the result; latency, body and traffic cover both legs, and the run summary counts followed redirects in redirects. Redirects to another host or to plain HTTP are not followed.
  • Omitted (every other network): default, each target runs over its own scheme and redirects are never followed.

The same table may record max_concurrency = N (an integer, 1–5,000): the highest concurrency the network sustained from one worker in campaign probe. campaign plan runs the network at min(--concurrency, N); without it the requested concurrency is used. Shifter records 2,000.

It may also record country_max_concurrency = { CC = n }: per country (an upper-case ISO code), the most requests that country's daily test holds at once (an integer, 1–5,000), for a gateway that refuses above a request-rate limit of the network's plan. The daily pace starts the country at most at n and its run never grows above it; the run's concurrency, and so its scope, stays the network's (daily tests, "Country ceiling").

It may also set the network's own IP-check URLs: echo_http = "http://…" and echo_https = "https://…" (each of its target's scheme, without credentials or a fragment). A generic_http or generic_https test of that network that would use the built-in URL (targets.py, ip-info.com/myip) runs at the network's URL instead: pulses, daily tests and atlas run alike. The target id stays and the run's target.url shows the URL used. Pulses and the network summaries count the run for the same target as before; a run outside a test batch (a daily test, atlas run) at a URL other than the built-in one forms its own cohort in the product lists, as any custom URL does (window_scoring.cohort_for, target_variant), and the network's pool counters start a new row (the pool hash includes the target). A URL given with the run (--url, a target row edited in /admin) is kept. The answer must still be one bare IP (surrounding whitespace, such as a final newline, is ignored). Networks without these keys run exactly as before.

A network whose gateway refuses an account a destination with a recognisable answer may declare it: forbidden_host = { header = "…", contains = "…" } (the gateway's answer header and the text in its value, matched without regard to case). On generic_http and generic_https, the gateway's own HTTP 403 with that header (its answer to the CONNECT or to a plain-HTTP request; never an answer from inside a tunnel) means our account may not reach the IP-check host. It is recorded as proxy_auth, like a refused login: the run is not judged (no outage), the pulse evaluator raises proxy_login_refused, the network is paused, a daily test so refused is not imported, and atlas daily resume-network refuses while the IP-check host is still refused (proxy_login.py). Without the key, a 403 stays a failure as before.

Three optional keys declare the network's answer classes; a run uses them only when it asks for answer classes (atlas run --answer-classes, ephemeral campaign rounds). HTTP 429 is a rate limit on every network and is never listed.

  • rate_limit_statuses = [469]: the network's own rate-limit statuses (distinct integers 400–599, not 429). Geonode lists 469.
  • rate_limit_connect = true: a gateway connection refusal (error proxy_connect, or connection when the gateway accepts a connection and drops it before answering) is a rate limit, counted under the proxy_connect signal, while the run had a success in the last 120 seconds; otherwise it stays a real connect error. DataImpulse sets it.
  • no_inventory_statuses = [465]: statuses the network sends when it has no exits in the requested country (distinct integers 400–599, not 429, none of them a rate-limit status). Geonode lists 465.

In Python, providers.grammar.answer_classes("geonode") returns AnswerClasses(rate_limits=("429", "469"), no_inventory=("465",)). Geonode also records max_concurrency = 500.

Non-default networks publish test_protocol in their run config; default run configs are unchanged. List the networks with a given protocol with atlas providers --protocol https-only (networks that cannot run a plain-HTTP test) or --protocol mixed; in Python, providers.grammar.grammar_ids_by_protocol().

A flag value whose words (split at the grammar's separator) include another flag's key or a reserved word is refused, so a value cannot add a flag to the credential. A country is two letters and cannot hold a separator, so it is exempt: ISO codes that equal a key, such as Oxylabs' CC and ST or DataImpulse's CR, load and render in the country slot.

Add a provider

  1. Write src/atlas/providers/grammars/<id>.toml: where flags go (username or password), the base template, separators, each flag's format and validation, session generation and gateway endpoints.
  2. Add configs/<id>.toml with credential environment names and defaults.
  3. Add a golden case to tests/grammars_cases.py and verify it with a small live run.

Providers whose behavior cannot be expressed as a grammar get a dedicated adapter registered in atlas.providers.registry.
