Shifter Residential adapter

Current bandwidth-based Residential Proxies product. Both Generic HTTP and Generic HTTPS accept this adapter over HTTP or SOCKS5. Provider parameters and session controls are independent of target definitions.

Start with the shared configuration

From the framework directory, use configs/shifter.toml for public settings and copy credentials.toml.example to .secrets/credentials.toml for private credentials. Edit the private copy locally. The account is the base ID, optionally prefixed with customer-; exclude country/session flags. The password is the original unescaped value, not a URL-encoded string.

mkdir -m 700 .secrets
cp credentials.toml.example .secrets/credentials.toml
chmod 600 .secrets/credentials.toml
# Edit .secrets/credentials.toml locally to replace the placeholders.

The private file is plaintext protected by filesystem permissions: current-user ownership, no group/other access, and no symlink. It is excluded from Git, source packages and remote test uploads. Only the example belongs in the community repository. Other providers use their own table in this file. When --credentials-file is supplied it takes precedence over the environment; without it, SHIFTER_ACCOUNT/SHIFTER_PASSWORD remain supported. Credentials are never copied into result metadata.

uv sync --locked --no-editable
uv run --no-editable milf-framework providers

# HTTP: US targeting only, default rotation, 5,000 requests.
uv run --no-editable milf-framework run \
  --provider-config configs/shifter.toml --target generic_http \
  --credentials-file .secrets/credentials.toml \
  --url http://ip-info.com/myip \
  --requests 5000 --concurrency 100 --param country=us

# HTTPS with one generated session per worker, lifetime 600 seconds.
uv run --no-editable milf-framework run \
  --provider-config configs/shifter.toml --target generic_https \
  --credentials-file .secrets/credentials.toml \
  --url https://ip-info.com/myip \
  --requests 10 --concurrency 2 --param country=us --param ttl=600 \
  --session-policy per_worker

# Explicit removal of an optional parameter configured in the TOML file:
# --param country=null

These commands send real traffic when run with credentials. Use --requests 5000 --concurrency 100 for a larger run when selected by your methodology. Automated tests and the 5,000-request processing benchmark use local/simulated responses.

Repeat --param name=value for each override. Booleans and numbers use JSON syntax; strings can be unquoted. null removes a file parameter. Parameters not supplied by either the file or overrides stay absent. --country remains a metadata label: use --param country=us to change targeting. Conflicting metadata labels are rejected. Static PROXY_URL runs remain supported.

--url overrides the echo-IP endpoint per run. Its HTTP/HTTPS scheme must match the target; the response must still be a plain IP address. IP Info remains the default when omitted. The effective URL is saved in the summary; URLs with embedded credentials or fragments are rejected. Use public, non-secret query parameters only.

Call it from a rule, scheduler or script

import asyncio
from milf_framework import JsonSink, RunConfig, load_provider, run

proxy = load_provider(
    "configs/shifter.toml",
    credentials_file=".secrets/credentials.toml",
    parameters={"country": "us"},
    session_policy="rotate",
)

async def measure():
    return await run(
        RunConfig("generic_http", proxy, requests=5_000, concurrency=100,
                  target_url="http://ip-info.com/myip"),
        JsonSink("results"),
    )

summary = asyncio.run(measure())
print(summary.to_dict())

Use the same API with generic_https. Configuration snapshots are immutable and safe to reuse in concurrent runs. Provider, product and requested country are derived from the adapter. Only Generic HTTP contributes unique-IP metrics and IP artifacts, as before.

Geographic values are lowercase; spaces become underscores. Full Geo supports all four geographic selectors; Country Geo supports country; Non-Geo supports none. Geo documentation.

A residential peer can disconnect before its TTL. Sessions are regional: sharing one SID across machines requires the same regional gateway to share one exit. Supplied IDs preserve their case and hyphens. Session documentation.

Validation is local and syntactic; it does not prove that an ASN/city is available or confirm account entitlements. Set pool only when known; incompatible geographic parameters then fail before traffic. ASCII letters, digits and underscores are accepted in geographic slugs. Session IDs additionally accept dots and hyphens; username flag delimiters, whitespace and template placeholders such as {SESSION} are rejected. Use a generated session policy instead of a placeholder. SOCKS5 credentials must fit its 255-byte authentication fields and the transport library's ASCII encoding.

Session policies

  • rotate: omit SID; Shifter rotates per request. Rotation does not guarantee every IP is unique.
  • fixed: require an explicit sid. This is also inferred when SID is supplied and no policy is specified. Reusing it intentionally shares the provider session.
  • per_request: generate a new SID for every request.
  • per_worker: generate one SID for each worker in a run; successive requests from that worker reuse it.
  • per_run: all workers in one run share one generated SID.

Without SID or an explicit policy, the adapter uses rotate. Generated IDs use the run UUID, policy and zero-based request/worker identity; separate runs do not share them. ttl requires fixed or generated sessions. A supplied SID cannot be combined with rotation or a generated policy. For stable entry routing choose a regional gateway, for example gateway = "fra".

Connection and account settings

Default gateway: p.shifter.io:443. Authentication uses customer-ACCOUNT plus selected flags and a separate password. Flag ordering is unrestricted. HTTP(S) and SOCKS5 use the same endpoint. These are connection settings, not additional username flags. Gateway documentation.

Optional regional gateways, all on port 443:

fra.p.shifter.io — Frankfurt
ams.p.shifter.io — Amsterdam
lon.p.shifter.io — London
nyc.p.shifter.io — New York
tor.p.shifter.io — Toronto
sgp.p.shifter.io — Singapore
blr.p.shifter.io — Bangalore
syd.p.shifter.io — Sydney

The default gateway selects a nearby region with failover. A regional hostname fixes entry location and has no automatic failover; it does not choose exit geography. Regional gateways.

Shifter describes 407 as credentials/flag errors, 502 as unavailable matching capacity, and 509 as exhausted bandwidth when extra traffic is disabled. Preserve status codes rather than silently broadening parameters or retrying measurements. Documented errors.

Implemented framework integration

  • One adapter per provider. It owns supported parameter names, normalization, validation, username formatting and endpoint resolution. Both current targets consume the same resolved connection.
  • Per-test optional parameters. Keep account credentials and gateway settings separate from test parameters. Emit only supplied flags; do not silently insert country, strict matching or a sticky session.
  • Explicit session policy. Support omitted SID, a supplied fixed SID, or generated IDs per request/per worker/per run. These policies belong to the framework; Shifter receives only the resulting sid and optional ttl.
  • Concurrency-safe resolution. Resolve credentials for each request. HTTP authentication can vary per request; SOCKS5 connections must retain their own resolved credentials without changing shared connector state.
  • Extensible parameters. Each provider defines its own schema rather than a global common subset. Support an explicit extra-flags mapping for future provider options, validating serialization without claiming undocumented flags work.
  • Reproducible results. Record provider/adapter version, safe effective parameters, gateway and session-generation policy. Keep passwords and complete authentication strings out of public artifacts.

Defaults: automatic gateway, HTTP proxy transport, empty optional-parameter set. A test explicitly requests US targeting or a session when needed. strict=false is omitted because only strict-true is documented. Pool capabilities remain account metadata; the supplied connection string does not establish which pool the account uses.

Result metadata and future providers

summary.json → config.provider_config records adapter/version, gateway, pool if known, normalized parameters, session policy and effective TTL. Account/password and full authentication strings are excluded; fixed SID and extra-flag values are redacted. Generated SIDs can be reconstructed from the run identity and adapter version. Parameter values in ordinary geographic fields are public configuration.

extra_flags is an explicit opt-in escape hatch for future flags, not a bypass for known-parameter validation. Names must be lowercase ASCII tokens; values must be single ASCII letter/digit/underscore tokens or integers/booleans. Reserved names and delimiter injection are rejected. This serializes a flag without claiming Shifter supports it; undocumented options may return 407. Values are redacted because their sensitivity is unknown.

New providers implement ProxySource: a stable scheme, a synchronous resolve(RequestContext) returning a ProxyConfig, and public() returning explicitly safe metadata. Register a factory in ProviderRegistry. Each factory owns its parameter schema; TOML settings, parameters, extra_flags, and credentials resolved from environment references are passed to it. Registering with the default registry also makes the provider available to the CLI. Targets require no provider-specific edits.

Custom transports now accept execute(target, *, context=None). The runner supplies RequestContext(run_id, request_index, worker_index); static transport implementations may ignore it. Resolve before each request. HTTP credentials belong to the request or CONNECT handshake. Dynamic SOCKS5 requests own their connectors, close them on completion/cancellation, and do not retain a cache of session IDs. Latency excludes credential resolution, connector allocation and post-response cleanup.

Optional selector discovery

A separate API lists countries, regions, cities and ASNs under /api/v1/residential/geo/. It requires an account API key, distinct from proxy authentication. Region, city and ASN lookups require country; cities optionally accept region. This can later refresh cached selector lists without entering the measured request path. Residential API reference.
